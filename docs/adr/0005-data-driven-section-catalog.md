# Data-Driven Section Catalog

The set of Section types a resume can contain is stored as data (a bundled array of `SectionCatalogItem`s, each carrying title, keywords, and Entry-field shape), not hardcoded into components. Each Resume Document draws its Sections from this catalog and can show, hide, add, or remove Sections and Entries per document without code changes. We chose a data-driven catalog over a hardcoded type registry because the user's template defines the exact output and they must be free to hide or extend Sections per application. For MVP the catalog is a bundled single-template constant rather than seeded from each import; seeding it from the uploaded template and making it editable/refreshable on re-import is deferred (see issue #1).
